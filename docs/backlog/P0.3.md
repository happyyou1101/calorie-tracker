# P0.3 — HTTPS 배포 파이프라인

## 목적

PWA가 제대로 작동하고 안드로이드에서 "공유하기"에 나타나려면 반드시 HTTPS(보안 인터넷 연결)로 배포되어야 합니다 (요구사항 5.2, 7). 따라서 로컬 개발 상태에서 벗어나 실제로 인터넷에 공개되는 배포 환경을 준비하고, 코드 변경 시 자동으로 배포되도록 파이프라인을 구축해야 합니다.

## 쉬운 설명

지금까지 만든 웹앱은 여러분의 컴퓨터에서만 보입니다. 하지만 휴대폰으로 접근하려면 인터넷에 공개해야 합니다. 

우리가 할 일:
1. 배포 서비스(Vercel, Netlify, 자신의 서버 등)를 선택합니다
2. 코드를 저장소(GitHub 등)에 올립니다
3. 배포 서비스가 자동으로 코드를 받아서 인터넷에 공개합니다 (HTTPS로)
4. 앞으로 코드를 변경하면 자동으로 새 버전이 배포됩니다
5. 휴대폰에서 그 URL로 접속하면 앱을 사용할 수 있습니다

## 필요한 입력

- P0.1에서 만든 웹앱 프로젝트
- GitHub, GitLab 등 Git 저장소 계정
- Vercel, Netlify, 또는 배포 서비스 계정
- (선택사항) 자신이 소유한 도메인

## 결과물

- 인터넷에 공개되는 HTTPS URL (예: `https://my-calorie-app.vercel.app/`)
- Git 저장소에 커밋된 코드
- 배포 서비스의 자동 배포 파이프라인 (코드 푸시 → 자동 배포)
- 재배포 방법에 대한 문서 (터미널 명령어 또는 웹 인터페이스 조작 설명)

## 선행 작업

**P0.1** (웹앱 스택 초기화): 로컬에서 실행되는 앱이 있어야 배포할 수 있습니다.

## 수행 순서

1. GitHub/GitLab 저장소 생성 (로컬 코드를 푸시할 저장소)
2. 로컬 프로젝트를 Git으로 초기화 및 첫 커밋
3. 원격 저장소에 푸시
4. 배포 서비스(Vercel/Netlify/기타) 선택 및 가입
5. 배포 서비스와 GitHub 저장소 연동
6. 배포 설정 (빌드 명령, 배포 디렉토리 등) 입력
7. 자동 배포 실행 및 URL 획득
8. 배포된 URL을 브라우저에서 열어 정상 작동 확인
9. HTTPS 표시(🔒) 확인
10. 배포 파이프라인 문서화

## done_when 확인 방법

- 배포된 HTTPS URL이 생성됨 (주소창에 🔒 표시)
- 브라우저에서 해당 URL에 접속하면 앱이 정상 렌더링됨
- 코드를 변경하고 Git에 푸시하면 자동으로 배포가 되는지 확인 가능 (배포 서비스 대시보드에서 "Deploy" 기록 확인 또는 재배포 명령 문서화)
- 배포 방법이 문서로 기록됨 (누가 봐도 따라할 수 있는 수준)

## 확인 질문

1. 배포 서비스는 어디를 사용할 예정입니까? (Vercel, Netlify, Firebase Hosting, 기타)
2. 자신의 도메인을 사용할 예정입니까?
3. 배포할 때마다 환경변수(`.env`)를 배포 서비스에 어떻게 전달할 예정입니까? (웹 인터페이스, 파일 업로드, GitHub Secret 등)

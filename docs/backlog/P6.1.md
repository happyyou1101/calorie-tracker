# P6.1 — 실사용 E2E 시나리오 실행

## 목적

P6에서 계획한 엔드투엔드 테스트 시나리오를 실제로 실행하고, 모든 기능이 정상 작동하는지 최종 검증합니다 (요구사항 4). 이는 실제 사용자 관점에서의 완성도 검증입니다.

## 쉬운 설명

마치 제품 출시 전 최종 점검하는 것처럼, 우리 앱이 사용자가 원하는 대로 작동하는지 실제로 해봅니다.

**테스트 시나리오**:
- 하루 동안 식사를 하면서 실제 사진으로 2회 이상 공유
- 누락된 끼니 1회를 수동으로 입력
- (선택) Notion에서 하나의 항목 수정
- 최종적으로 Notion의 데이터와 앱이 표시하는 정보가 일치하는지 확인
- 목표 초과 시 알림 수신 (또는 초과하지 않았다면 초과할 때까지 추가)

## 필요한 입력

- P1.4, P2.2, P3.3, P4.3, P5.2 모두 완료 상태
- 실제 안드로이드 기기 (에뮬레이터는 덜 현실적)
- 실제 식사 사진 또는 테스트 음식 사진 2개 이상
- 테스트 가능한 실제 Notion 데이터베이스

## 결과물

- 테스트 실행 기록:
  - 날짜, 시간
  - 수행한 작업 (사진 공유, 수동 입력 등)
  - 결과 (Notion 기록 확인, 알림 수신 등)
  - 발견된 문제
  
- 최종 증거물 (스크린샷):
  - Notion 표에 당일 기록된 모든 줄
  - 정확한 하루 총합
  - (알림 발송된 경우) 알림 스크린샷

## 선행 작업

**P1.4** (실기기 공유하기 목록 노출 확인): 앱이 공유 목록에 나타나야 함
**P2.2** (다중 음식 합산): 여러 음식 합산이 정상 작동해야 함
**P3.3** (하루 총합 재계산): 총합 재계산이 정상 작동해야 함
**P4.3** (초과 알림): 초과 알림이 발송되어야 함
**P5.2** (지난 날짜 수동 추가): 수동 추가가 정상 작동해야 함

## 수행 순서

1. 테스트 계획 확인 (위 시나리오)
2. 실기기에서 앱이 정상 설치되어 있는지 확인
3. **시나리오 1: 오전 식사 사진 촬영 및 공유**
   - 갤러리에서 사진 선택
   - "공유" → 이 앱 선택
   - AI가 음식을 인식했는지 확인
   - Notion에 행이 생성되었는지 확인
4. **시나리오 2: 점심 식사 사진 촬영 및 공유**
   - 같은 방식으로 반복
   - Notion에 두 번째 줄이 추가되었는지 확인
   - 하루 총합이 업데이트되었는지 확인
5. **시나리오 3: 수동 입력**
   - 앱에서 "음식 추가" 버튼 클릭
   - 과거 식사(예: 간식) 추가
   - Notion 확인
   - 하루 총합 재계산 확인
6. **시나리오 4: (선택) Notion 직접 수정**
   - Notion 웹사이트에서 항목 하나 수정
   - 앱에서 반영 확인
7. **시나리오 5: 목표 초과 (필요시)**
   - 누적값이 목표를 초과하도록 음식 추가
   - 알림 수신 확인

## done_when 확인 방법

- 당일 기록된 모든 음식이 Notion에 정확히 나타남 (사진 공유 + 수동 입력 포함)
- Notion의 하루 총합이 정확함 (모든 음식 칼로리의 합)
- (목표 초과 시) 초과 알림이 휴대폰에서 수신됨
- 앱과 Notion의 데이터가 일치함
- 에러/충돌 없이 모든 기능이 정상 작동함

## 확인 질문

1. 테스트 기간은 언제로 설정합니까? (오늘 하루, 특정 날짜 등)
2. 테스트 중 발견된 버그는 P6.1 완료 전에 모두 수정해야 합니까?
3. 성능 관점(로딩 속도, 메모리 사용 등)도 평가해야 합니까?
4. 테스트 결과를 보고서로 정리할 예정입니까?

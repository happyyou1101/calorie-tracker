## 목적

PWA가 웹사이트처럼 보이지 않고 진짜 앱처럼 동작하려면 Service Worker가 필요합니다. Service Worker는 백그라운드에서 실행되어 앱이 오프라인에서도 작동하고, 브라우저 밖의 설치 가능한(installable) 앱으로 인식되도록 합니다. 이를 통해 사용자는 "홈 화면에 추가(A2HS, Add to Home Screen)" 기능으로 앱을 설치할 수 있습니다.

## 쉬운 설명

일반적인 웹사이트는 인터넷이 없으면 아무것도 할 수 없습니다. 하지만 Service Worker가 있는 PWA는 마치 진짜 앱처럼 오프라인 상태에서도 기본 기능이 작동할 수 있습니다.

또한 Service Worker 덕분에 안드로이드 크롬이 자동으로 "이것은 설치 가능한 앱이다"라고 인식하고 "홈 화면에 추가" 프롬프트를 보여줍니다. 사용자가 그 버튼을 누르면 앱이 홈 화면에 아이콘으로 추가됩니다.

## 필요한 입력

- P1.1 (Web App Manifest + share_target 설정)이 완료된 상태
- HTTPS로 배포된 웹앱

## 결과물

- `public/sw.js` (또는 `src/serviceWorker.ts` 등) Service Worker 파일
- 앱 시작 코드에서 Service Worker를 등록하는 JavaScript:
```javascript
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js');
}
```
- 실제 안드로이드 크롬에서 "홈 화면에 추가" 프롬프트 자동 표시

## 선행 작업

**P1.1** (Web App Manifest + share_target 설정): Manifest가 필요 조건입니다.

## 수행 순서

1. `public/sw.js` 파일 생성
2. 기본 Service Worker 코드 작성 (install, activate, fetch 이벤트 처리)
3. 앱의 초기화 코드에서 Service Worker 등록 로직 추가
4. 로컬 개발 서버에서 DevTools "Application" 탭의 "Service Workers" 섹션 확인
5. 배포 후 실제 안드로이드 크롬에서 앱 접속
6. 크롬 메뉴 또는 주소창 옆에 "설치" 버튼/프롬프트 나타나는지 확인
7. "홈 화면에 추가" 선택 후 앱 설치 확인

## done_when 확인 방법

- 로컬 DevTools의 "Application" → "Service Workers" 탭에서 Service Worker가 "activated and running" 상태로 표시됨
- 배포된 앱을 안드로이드 크롬에서 열었을 때 "홈 화면에 추가" 프롬프트 자동 표시 (또는 메뉴에서 수동 선택 가능)
- 앱을 설치한 후 홈 화면에 앱 아이콘이 추가되고, 그것을 누르면 앱이 실행됨
- 앱이 전체 화면(주소창 없이) 스탠드얼론 모드로 실행됨

## 확인 질문

1. Service Worker 캐싱 전략을 정할 예정입니까? (network-first, cache-first, stale-while-revalidate 등)
2. 오프라인 상태에서 앱이 어느 정도 기능해야 합니까? (UI만 표시, 기본 기능까지)

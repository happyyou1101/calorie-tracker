# P5.3 — Notion 직접 수정 반영 방식 구현

## 목적

사용자가 Notion 웹사이트에서 직접 "돈까스"를 "국밥"으로 수정했다면, 앱도 그 변경을 알고 하루 총합을 재계산해야 합니다 (요구사항 5.7). 이를 구현하는 방법은 두 가지입니다: 실시간 감지(웹훅)와 주기적 감지(폴링). 요구사항 9에서 미확정이므로 이 작업에서 선택해야 합니다.

## 쉬운 설명

Notion의 웹훅 또는 폴링으로 "Notion 데이터가 변경됐나?"라고 주기적으로 또는 실시간으로 확인합니다.

변경이 감지되면:
1. 변경된 행의 필드 추출 (메뉴, 칼로리 등)
2. 해당 날짜의 하루 총합 재계산
3. 필요시 목표 초과 여부도 재확인

## 필요한 입력

- P3.3 (하루 총합 재계산 로직) 완료
- Notion의 변경 감지 방식 선택 (웹훅 vs 폴링)

## 결과물

- **웹훅 방식 선택 시**:
  - Notion Webhook 설정 (앱 서버의 엔드포인트 등록)
  - 변경 이벤트 수신 및 처리 로직
  
- **폴링 방식 선택 시**:
  - 주기적(예: 30초마다) Notion 데이터 조회 함수
  - 변경 감지 로직 (이전 상태 vs 현재 상태 비교)
  - 변경 발견 시 하루 총합 재계산

- 테스트: Notion에서 항목을 수정 후 앱이 감지하는지 확인

## 선행 작업

**P3.3** (하루 총합 재계산): 재계산 로직 필요

## 수행 순서

1. **변경 감지 방식 결정** (웹훅 vs 폴링)
2. **웹훅 방식 선택 시**:
   - Notion 앱 설정에서 Webhook URL 등록
   - 서버 엔드포인트 구현 (변경 이벤트 수신)
   - 이벤트 파싱 및 데이터 추출
3. **폴링 방식 선택 시**:
   - 타이머 설정 (예: 30초마다)
   - 주기적으로 Notion 데이터 조회
   - 데이터 버전/시간 비교로 변경 감지
4. 변경 감지 시 P3.3의 재계산 함수 호출
5. 테스트

## done_when 확인 방법

- Notion 웹사이트에서 항목을 직접 수정 (메뉴명 또는 칼로리)
- 앱이 변경을 감지함 (웹훅이라면 즉시, 폴링이라면 설정된 주기 내에)
- 해당 날짜의 하루 총합이 자동으로 재계산되어 반영됨

## 확인 질문

1. 변경 감지 방식은 어떻게 할 예정입니까?
   - 웹훅 (실시간, 더 정확하지만 백엔드 필요)?
   - 폴링 (주기적, 더 간단하지만 지연 있음)?
2. 폴링 선택 시 주기는 얼마로 할 예정입니까? (30초, 1분, 5분 등)
3. 대량 변경(예: 여러 행 동시 수정)이 발생했을 때 모두 감지해야 합니까?
4. Notion 직접 수정 시 데이터 버전이나 "last_edited_time" 같은 메타데이터를 사용할 예정입니까?

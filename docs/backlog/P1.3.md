# P1.3 — 공유 인텐트 수신 엔드포인트 (이미지 수신·업로드 시각 기록)

> 이 문서는 설명용입니다. 이 문서 작성 완료가 P1.3의 개발 완료를 뜻하지 않습니다.
> 개발 완료 여부는 backlog.json의 status 필드(CLI로 조회)로만 판단하세요.
> 기준 버전(source_sha256): 1105d02dad40e288cb774f5f37c661ea4d20d12d5e1f8caf1bc663856848a36c

## 목적

사용자가 갤러리에서 사진을 공유했을 때, 그 사진이 어디서 처리되어야 합니까? P1.1의 Manifest에서 `share_target.action` 경로(예: `/share`)로 지정한 엔드포인트가 바로 그 사진을 받는 곳입니다. 이 엔드포인트는 사진을 수신하고, 업로드 시각(현재 시각)을 자동 기록하고, 다음 단계(AI 추정, P2)로 전달해야 합니다.

## 쉬운 설명

사진 공유 과정은 다음과 같습니다:
1. 사용자: 갤러리에서 사진을 "공유하기" → 이 앱 선택
2. 안드로이드: 사진 파일을 이 앱의 `share_target.action` 경로로 POST 전송
3. **우리 앱**: `/share` 엔드포인트가 사진을 받음
4. **우리 앱**: 받은 시각을 "업로드 시각"으로 자동 기록
5. **우리 앱**: 사진을 AI 추정 단계로 전달

이 작업에서는 3번과 4번을 구현합니다.

## 필요한 입력

- P1.1 (Manifest 설정, 특히 `share_target.action` 경로)이 완료된 상태
- 웹앱 백엔드 또는 프론트엔드 기술 스택 결정 (Node.js/Express, Python/Flask, 순수 JavaScript 등)

## 결과물

- `/share` (또는 P1.1에서 정한 경로) 엔드포인트 구현
- 엔드포인트에서:
  - 공유된 이미지 파일 수신
  - 현재 시각(timestamp) 자동 기록
  - 응답 예시:
```json
{
  "success": true,
  "timestamp": "2026-09-15T14:30:45Z",
  "imageName": "shared_image_20260915_143045.jpg"
}
```
- (사진 원본은 저장하지 않음, 텍스트 정보만 전달 — 요구사항 5.3, 7)

## 선행 작업

**P1.1** (Web App Manifest + share_target 설정): `share_target.action` 경로를 알아야 엔드포인트를 만들 수 있습니다.

## 수행 순서

1. Manifest의 `share_target.action` 경로 확인 (예: `/share`)
2. 해당 경로의 엔드포인트 구현 (백엔드 프레임워크 사용 또는 프론트엔드 라우팅)
3. 엔드포인트에서 multipart/form-data 형식 파일 수신 처리
4. 수신 시각(현재 시각) 자동 기록 및 기록 저장/전달
5. 테스트: 브라우저 개발자 도구에서 파일 공유 시뮬레이션 또는 curl로 테스트
6. 배포 후 실제 안드로이드에서 공유 테스트

## done_when 확인 방법

- 브라우저 또는 테스트 도구(curl 등)에서 이미지 파일을 해당 엔드포인트로 전송했을 때 정상 응답(200, JSON)이 나타남
- 응답에 업로드 시각(timestamp)이 올바르게 기록되어 있음
- 로그/개발자 도구에서 전송된 파일이 수신된 것을 확인 가능
- (사진 파일 자체가 디스크에 저장되지 않았는지 확인 — 요구사항 7)

## 확인 질문

1. 백엔드는 클라우드(예: Node.js + Express)일 예정입니까, 아니면 클라이언트 사이드(브라우저)에서만 처리할 예정입니까?
2. 파일 수신 후 AI 추정 단계로의 전달 방식은 어떻게 할 예정입니까? (즉시 API 호출, 큐에 저장 후 비동기 처리 등)
3. 업로드 시각의 타임존은 어떻게 할 예정입니까? (UTC, 사용자 로컬 타임존 등)

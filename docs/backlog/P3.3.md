# P3.3 — 하루 총합 자동 재계산 로직

## 목적

칼로리 기록은 하루 내내 계속 들어옵니다. 아침, 점심, 저녁, 간식... 매번 새로운 행이 Notion에 추가될 때마다 "오늘 총 칼로리"가 다시 계산되어야 합니다 (요구사항 5.4, 5.6, 5.7). 또한 사용자가 과거 날짜의 항목을 수정했을 때도 그 날짜의 총합이 재계산되어야 합니다.

## 쉬운 설명

예시:
- 14:30 아침 공유: 돈까스 600kcal → 오늘 총: 600
- 13:00 점심 공유: 국밥 500kcal → 오늘 총: 1100 (600+500)
- 19:00 저녁 공유: 치킨 700kcal → 오늘 총: 1800 (600+500+700)

또한 자정이 중요합니다. 23:59에 먹은 음식과 00:01에 먹은 음식은 다른 날짜로 구분되어야 합니다.

## 필요한 입력

- P3.2 (Notion API로 신규 행 생성) 완료 상태
- Notion에서 자동 계산(formula) 지원 여부 결정 또는 앱에서 수동 계산하는 방식 결정

## 결과물

- 날짜별로 행들을 필터링하고 칼로리를 합산하는 함수:
```javascript
async function recalculateDailyTotal(date) {
  const records = await notion.databases.query({
    database_id: DB_ID,
    filter: {
      property: "Date",
      date: { equals: date }
    }
  });
  const total = records.results.reduce((sum, r) => 
    sum + r.properties.Calories.number, 0
  );
  // 각 행의 "하루총합" 필드 업데이트 또는 별도의 요약 행 업데이트
}
```
- 테스트: 같은 날짜에 여러 행을 추가할 때마다 총합이 정확히 재계산되는지 확인

## 선행 작업

**P3.2** (Notion API로 신규 행 생성): 이미 생성된 행들을 쿼리할 수 있어야 합니다.

## 수행 순서

1. 재계산 방식 결정 (Notion formula vs 앱에서 수동 계산)
2. **Notion formula 선택 시**:
   - Notion DB에서 "Daily Total" 필드를 formula 타입으로 설정
   - 수식 작성: 같은 날짜의 모든 행의 Calories를 합산
3. **앱에서 수동 계산 시**:
   - 새 행 생성 후 해당 날짜의 모든 행을 쿼리
   - 칼로리를 합산
   - 모든 행의 "하루총합" 필드 업데이트
4. 자정 경계 처리 (UTC 기준 또는 로컬 타임존)
5. 테스트: 같은 날짜에 행을 추가할 때마다 총합 변화 확인

## done_when 확인 방법

- 같은 날짜에 여러 행을 추가할 때마다:
  - 첫 번째 행 후 하루총합: 첫 번째 값
  - 두 번째 행 후 하루총합: 첫+두 번째 값
  - 세 번째 행 후 하루총합: 첫+두+세 번째 값
- 자정 기준으로 날짜 경계가 정확히 분리됨 (23:59와 00:01이 다른 날짜로 표시)
- 과거 날짜의 행을 수정했을 때 그 날짜의 총합도 재계산됨

## 확인 질문

1. 재계산 방식은 Notion formula를 사용할 예정입니까, 아니면 앱에서 계산할 예정입니까?
2. 모든 행의 "하루총합" 필드를 업데이트할 건가요? (즉, 같은 날짜의 모든 행이 같은 값)
   - 아니면 한 날짜마다 하나의 "요약" 행을 만들어서 거기에만 총합을 입력할 건가요?
3. 수정 시 재계산은 실시간(즉시)이어야 합니까, 아니면 주기적(예: 매 분)으로 해도 괜찮습니까?
4. 타임존은 UTC를 사용합니까, 아니면 사용자의 로컬 타임존을 사용합니까?

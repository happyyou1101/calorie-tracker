# P1.1 — Web App Manifest + share_target 설정

> 이 문서는 설명용입니다. 이 문서 작성 완료가 P1.1의 개발 완료를 뜻하지 않습니다.
> 개발 완료 여부는 backlog.json의 status 필드(CLI로 조회)로만 판단하세요.
> 기준 버전(source_sha256): 1105d02dad40e288cb774f5f37c661ea4d20d12d5e1f8caf1bc663856848a36c

## 목적

PWA가 안드로이드 OS의 "공유하기" 목록에 나타나려면 `manifest.json` 파일에서 `share_target` 속성을 명시해야 합니다. 이것은 앱이 이미지 파일을 받을 준비가 되어 있다고 OS에게 알리는 신호입니다.

## 쉬운 설명

안드로이드 폰의 설정을 생각해보세요. 예를 들어 폰에 새로운 메신저 앱을 설치하면, 안드로이드는 자동으로 그 앱이 메시지/파일을 받을 수 있다는 것을 알고 "공유하기" 목록에 추가합니다.

마찬가지로 PWA도 `manifest.json`이라는 "설정 파일"에서 "나는 이미지 파일을 받을 수 있습니다"라고 명시하면, 안드로이드가 자동으로 이 앱을 "공유하기" 목록에 추가합니다.

이 작업은 그 설정 파일을 정확히 작성하는 것입니다.

## 필요한 입력

- P0.3 (HTTPS 배포 파이프라인)이 완료된 상태
- 앱의 이름, 설명 (선택사항)
- 앱 아이콘 이미지 (192x192, 512x512 권장)

## 결과물

- `public/manifest.json` 또는 유사한 경로의 Manifest 파일
- 파일 내용 예시:
```json
{
  "name": "칼로리 기록 앱",
  "short_name": "칼로리",
  "start_url": "/",
  "display": "standalone",
  "share_target": {
    "action": "/share",
    "method": "POST",
    "enctype": "multipart/form-data",
    "params": {
      "files": [
        {
          "name": "image",
          "accept": ["image/*"]
        }
      ]
    }
  }
}
```
- HTML의 `<head>` 태그에 Manifest 링크: `<link rel="manifest" href="/manifest.json">`

## 선행 작업

**P0.3** (HTTPS 배포 파이프라인): Manifest 검증 도구들이 HTTPS 접근을 요구하기 때문입니다.

## 수행 순서

1. `public/manifest.json` 파일 생성
2. 기본 메타데이터 입력: 이름, 아이콘, 시작 URL 등
3. `share_target` 섹션 추가: action 경로, 메서드(POST), 이미지 파일 수락 설정
4. HTML의 `<head>`에 manifest.json 링크 추가
5. Manifest 검증 도구(web.dev Lighthouse 등)로 유효성 검사
6. 배포된 앱에 접속해 DevTools의 Application 탭에서 Manifest 확인

## done_when 확인 방법

- Manifest 파일이 `/public/manifest.json`에 존재함
- Manifest 검증 도구(Lighthouse 등)에서 유효성 통과
- 배포된 앱의 DevTools에서 "Application" → "Manifest" 탭을 열면 올바른 JSON이 표시됨
- `share_target` 속성이 명확히 정의되어 있음

## 확인 질문

1. 앱의 공식 이름과 약자 이름은 무엇입니까?
2. 앱 아이콘은 이미 준비되었습니까? (PNG, 192x192, 512x512)
3. 공유 인텐트를 받을 엔드포인트 경로는 무엇으로 할 예정입니까? (예: `/share`, `/upload`)

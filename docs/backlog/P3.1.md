## 목적

Notion 데이터베이스를 만들기 전에 "어떤 구조로 만들 것인가"를 정해야 합니다. 요구사항 6에서 명시한 5개의 필드(날짜, 시간, 메뉴, 칼로리, 하루총합)를 Notion의 타입에 맞게 정의하는 작업입니다.

## 쉬운 설명

Notion 표를 만들 때, 엑셀처럼 열(컬럼)을 먼저 정의합니다:
- "날짜" 열: 날짜 타입
- "시간" 열: 시간/텍스트 타입
- "메뉴" 열: 텍스트 타입
- "칼로리" 열: 숫자 타입
- "하루총합" 열: 숫자 또는 수식(formula) 타입

이 작업은 Notion에서 실제로 이 표를 생성하고 필드를 정의하는 것입니다.

## 필요한 입력

- P0.2 (Notion API 토큰과 Database ID) 완료
- Notion 계정 접근
- 데이터베이스 구조에 대한 최종 결정 (단일 DB vs 월별 분리, 하루총합 계산 방식 등)

## 결과물

- Notion에 실제 데이터베이스 생성
- 다음 5개 필드 정의 및 타입 설정:
  - "Date" (날짜 타입, 자정 기준)
  - "Time" (시간 타입, 또는 텍스트 "HH:MM")
  - "Menu" (텍스트 타입, 단라인)
  - "Calories" (숫자 타입, 정수)
  - "Daily Total" (숫자 타입, 또는 수식으로 자동 계산)
- Database ID 확인 및 기록 (API에서 사용하기 위해)

## 선행 작업

**P0.2** (API 키 관리): Notion Integration 토큰 필요

## 수행 순서

1. Notion 웹 페이지에 접속, "새 데이터베이스" 생성
2. 테이블 형식(Table) 선택
3. 다음 5개 필드 추가:
   - "Date" (Date 타입)
   - "Time" (Text 타입, 또는 Time 타입)
   - "Menu" (Text, 단라인)
   - "Calories" (Number)
   - "Daily Total" (Number 또는 Formula)
4. Database ID 확인 (URL에서 추출 또는 API 설정에서 확인)
5. Notion Integration에서 이 DB에 접근 권한 부여
6. 테스트: API로 데이터 삽입 시도 (P3.2에서 진행)

## done_when 확인 방법

- Notion 웹사이트에 실제 데이터베이스가 보임
- 5개 필드가 모두 정의되어 있고 타입이 올바름
- Database ID가 확인 가능하고 기록됨
- Notion Integration이 이 DB에 접근 가능한 상태 (권한 설정 완료)

## 확인 질문

1. 하나의 DB에 모든 날짜의 기록을 누적할 건가요, 아니면 월별로 분리할 건가요?
2. "하루총합" 필드를 Notion의 자동 수식(formula)으로 계산할 건가요, 아니면 앱에서 계산해서 입력할 건가요?
3. 다른 필드(메뉴, 칼로리 등)를 추후 수정할 때 하루총합도 자동으로 재계산되도록 트리거하는 방식은?
4. 사진 원본은 저장하지 않는다고 했으므로, Attachment 필드는 만들지 않아도 되는 건가요?

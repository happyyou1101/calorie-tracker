# P4.3 — 초과 알림 발송 (웹 푸시 등)

> 이 문서는 설명용입니다. 이 문서 작성 완료가 P4.3의 개발 완료를 뜻하지 않습니다.
> 개발 완료 여부는 backlog.json의 status 필드(CLI로 조회)로만 판단하세요.
> 기준 버전(source_sha256): 1105d02dad40e288cb774f5f37c661ea4d20d12d5e1f8caf1bc663856848a36c

## 목적

P4.2에서 초과를 감지했다면, 이제 사용자의 휴대폰에 실제로 알림을 보내야 합니다 (요구사항 5.5). 웹 푸시 알림, 앱 내 알림 등 여러 방식이 있으며, 요구사항 9에서는 구체적 방식이 미확정이므로 이 작업에서 결정해야 합니다.

## 쉬운 설명

마치 카톡이 "새 메시지" 알림을 보내는 것처럼, 우리 앱도 "목표 초과!" 알림을 보냅니다. 사용자가 다른 앱을 사용 중이어도 휴대폰 상단에 알림이 뜹니다.

## 필요한 입력

- P4.2 (초과 감지) 완료
- 알림 방식 선택 (웹 푸시, 이메일, 앱 내 알림 등)
- 선택 방식에 따른 라이브러리/서비스 (예: Firebase Cloud Messaging, Web Push API 등)

## 결과물

- 알림 발송 함수:
```javascript
async function sendExceededNotification() {
  const title = "칼로리 목표 초과!";
  const options = {
    body: "오늘 하루 칼로리 목표를 초과했습니다.",
    icon: "/icon-192x192.png",
    badge: "/badge-72x72.png"
  };
  
  if ('serviceWorker' in navigator && 'Notification' in window) {
    const registration = await navigator.serviceWorker.ready;
    registration.showNotification(title, options);
  }
}
```
- 사용자 권한 요청 (브라우저가 알림을 보내도 되는지 묻기)
- 테스트: 실제 휴대폰에서 초과 시 알림 수신 확인

## 선행 작업

**P4.2** (초과 감지): 초과 신호가 필요합니다.

## 수행 순서

1. 알림 방식 결정 (웹 푸시, 앱 내 토스트 등)
2. **웹 푸시 방식 선택 시**:
   - Notification API 지원 확인
   - 사용자로부터 알림 권한 요청
   - 알림 발송 코드 작성
3. **앱 내 알림 방식 선택 시**:
   - Toast/modal 컴포넌트 구현
   - 3초 후 자동 사라지도록 설정
4. **이메일/SMS 방식 선택 시**:
   - 외부 서비스(SendGrid, Twilio 등) 연동
5. 테스트: 실제 휴대폰에서 알림 수신

## done_when 확인 방법

- 목표를 초과하는 순간 실기기(안드로이드 폰)에서 알림이 뜸
- 알림 제목과 본문이 명확하고 읽기 쉬움
- 알림을 탭하면 앱으로 돌아옴 (또는 적절한 화면으로 이동)
- 알림 권한 요청이 한 번만 나타나고, 이후에는 자동으로 발송됨

## 확인 질문

1. 알림 방식은 무엇으로 할 예정입니까?
   - 웹 푸시 (브라우저/PWA 알림)?
   - 앱 내 토스트 메시지?
   - 이메일?
   - SMS?
   - 기타?
2. 웹 푸시 선택 시 백엔드 서비스(Firebase 등)를 사용할 건가요, 아니면 브라우저 기본 API만?
3. 알림 소리, 진동, 불빛 등 추가 기능이 필요합니까?
4. 알림을 반복해서 보낼 건가요? (예: 5분마다 "아직 초과된 상태입니다")

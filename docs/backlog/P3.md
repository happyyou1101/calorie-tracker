# P3 — Notion 기록 연동 및 하루 총합 재계산

> 이 문서는 설명용입니다. 이 문서 작성 완료가 P3의 개발 완료를 뜻하지 않습니다.
> 개발 완료 여부는 backlog.json의 status 필드(CLI로 조회)로만 판단하세요.
> 기준 버전(source_sha256): 1105d02dad40e288cb774f5f37c661ea4d20d12d5e1f8caf1bc663856848a36c

## 목적

AI가 추정한 음식명과 칼로리를 어디에 저장할 것입니까? 답은 Notion 표입니다 (요구사항 3, 5.3). 사용자는 이미 Notion을 사용 중이므로, 그 곳에 자동으로 기록하면 별도 앱이 필요 없습니다. 또한 각 날짜별로 하루 총 칼로리를 자동으로 계산해서 표시해야 합니다 (요구사항 5.4).

## 쉬운 설명

일과 끝나고 저녁을 먹으면서 휴대폰 카메라로 식사를 찍습니다. 앱은 그 사진을 받아서:
1. AI에게 "이게 뭐에요?" 묻습니다 (P2 완료)
2. AI의 답변을 Notion 표에 한 줄로 기록합니다
3. 그 날의 모든 기록을 모아서 "오늘 총 칼로리"를 계산합니다

오늘 낮에 500kcal, 저녁에 600kcal을 먹었다면, 오늘의 총합은 1100kcal이 됩니다.

## 필요한 입력

- P0 (기본 인프라) 완료, 특히 P0.2 (Notion API 토큰과 Database ID) 필요
- P2 (AI 추정) 완료 상태
- Notion 데이터베이스 생성 완료 및 ID 확보

## 결과물

- Notion에 실제로 기록되는 행:
  - 날짜
  - 시간 (업로드 시각)
  - 메뉴 (추정된 음식명)
  - 칼로리 (추정된 칼로리)
  - 하루 총합 (자동 계산된 값)
- Notion 표가 항상 최신 상태로 유지됨 (항목 추가/수정 시 총합 재계산)

## 선행 작업

**P0** (프로젝트 기반 구축): API 키 관리와 배포 필요
**P2** (사진 → 칼로리 추정): AI 추정 결과 필요

## 수행 순서

1. **Notion DB 스키마 설계** (P3.1): 5개 필드(날짜·시간·메뉴·칼로리·하루총합) 정의
2. **Notion API로 신규 행 생성** (P3.2): AI 추정 결과를 Notion에 INSERT
3. **하루 총합 재계산 로직** (P3.3): 자정 기준으로 날짜 구분, 합산 계산

## done_when 확인 방법

- Notion 데이터베이스에 실제 행이 생성됨 (5개 필드 모두 채워짐)
- 같은 날짜에 여러 행을 추가했을 때 하루 총합이 정확히 계산되고 표시됨
- 자정을 넘은 시간대 데이터가 새로운 날짜로 분리됨

## 확인 질문

1. Notion 데이터베이스는 하나로 유지할 건가요, 아니면 월별로 나눌 건가요? (스펙 §9 미확정)
2. "하루 총합" 필드는 Notion에서 자동 계산(formula)으로 할 건가요, 아니면 앱에서 계산해서 입력할 건가요?
3. 사진 파일 자체는 Notion에 저장할 건가요? (스펙 7에서는 "사진 원본은 저장하지 않는다"고 했으므로 NO인 것 같습니다)
